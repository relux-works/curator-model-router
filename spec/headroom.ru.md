# Факты использования и распределение с учётом запаса: спецификация

Статус: **ЧЕРНОВИК**, 2026-10-01.

**Исходные решения:** решения оператора от 2026-09-30 (решение оператора):

- D1: записи использования — это факты, которыми владеет agents-management, а роутер их потребляет;
- D2: без зависимости от CodexBar;
- требование 2: распределение с учётом запаса.

**Входы:**

- `wiki/research/2026-10-01-usage-limits-awareness.md` (*L1*), о том, как каждый харнесс показывает использование;
- дизайн квот провайдеров (`providerquota`) в task-board, проверенный 2026-09-08;
- LP-D9, блок доступности и его советующее правило.

---

## 0. Цель

Система должна в каждый момент знать, сколько осталось от каждой подписки, для каждого `(runtime, managed home)`, и использовать это для распределения работы:

- предпочитать мощность, которая иначе сгорит неиспользованной к следующему сбросу;
- беречь подписку, которая горит быстрее, чем позволяет её окно;
- держать резерв для оркестраторов и ревьюеров;
- распределять параллельные запуски по подпискам.

**Жёсткие фильтры не меняются:** допуск оператора плюс реактивный слой лимитов (`providerlimits`). Запас упорядочивает кандидатов и никогда никого не допускает и не убирает.

## 2. Нативные поверхности

Из L1 §1, проверено 2026-10-01. Каждый харнесс показывает pull-чтение и, где есть, push в хостимой сессии.

| Среда выполнения | Pull-чтение (проба) | Push в хостимой сессии | Оценка |
| --- | --- | --- | --- |
| codex | app-server `account/rateLimits/read` (замороженный план из передачи EPIC §3) | `account/rateLimits/updated`; `rate_limits` в `TokenCountEvent` | exact, объявленная схема |
| claude | `claude -p --output-format json --no-session-persistence --setting-sources "" --strict-mcp-config "/usage"`, плюс близнец `usage_report`, когда CLI его прикладывает | `rate_limit_event` в stream-json | только проценты; exact с `usage_report` |
| muse | MSP `usage/read` через `muse serve` (1.4.1) | MSP `usage/changed` | последнее наблюдённое |
| agy | `agy --output-format json --mode plan --print-timeout 2m --print="/usage"` | нет | наблюдённая схема |
| gemini | нет без чтения его файла учётных данных | нет | `not_supported` |

**Muse.** Строка `usage/read` заменяет решение D5 эпика (Muse `not_supported`), принятое на Muse 1.0.3, до появления этого метода.

**Без инференса.** Проба никогда не делает вызовов инференса. Нужен ли чтению Muse один `session/start`, когда `usage` отсутствует, — эмпирическая проверка из L1 §5. W3 решает это по свидетельствам.

## 3. Запись: контракт производителя

Одна запись на `(runtime, managed home)`. Проекция на стороне роутера (§3.1) читает эти поля; производитель может нести больше.

```jsonc
{
  "identity": "9f1c2ab73d40e5b8",  // providerlimits Identity.Key, or "runtime-<id>" when the harness declares no home
  "runtime": "codex",
  "state": "exact",                // exact | percent_only | last_observed | not_supported | unavailable
  "authenticated": true,           // from the read itself, never from a file's existence; "unknown" when unproven
  "plan": "pro",                   // vendor plan or tier id, verbatim
  "windows": [
    {"id": "session", "scope": "all", "minutes": 300,   "used_percent": 28, "resets_at": "2026-10-01T17:15:00Z", "observed_at": "2026-10-01T12:00:00Z"},
    {"id": "weekly",  "scope": "all", "minutes": 10080, "used_percent": 59, "resets_at": "2026-10-05T17:00:00Z", "observed_at": "2026-10-01T12:00:00Z"}
  ],
  "credits": {"balance": 12.5, "unit": "credits", "unlimited": false},  // optional, when the harness reports it
  "observed_at": "2026-10-01T12:00:00Z",  // the OLDEST window measurement time
  "retrieved_at": "2026-10-01T12:00:03Z", // when the probe or push delivered this record
  "ttl_s": 600,
  "source": "codex-app-server",    // codex-app-server | claude-print-usage | msp-usage-read | agy-print-usage | session-push
  "failures": [],                  // the latest failed reads or pushes, each with its time
  "digest": "sha256:…"             // over the parsed windows only
}
```

**Окна.**

- Идентификаторы и области действия окон — вендорские, дословно.
- `used_percent` может превышать 100: Muse документирует значения больше 100 как допустимые.
- Окно, ограниченное моделью, отображается на модели реестра через версионированную карту областей действия (§3.1). Её источник — таблица отображения из дизайна отображения областей действия провайдеров, когда та появится.

**Каждое окно несёт собственный `observed_at`: время замера ИСТОЧНИКА, никогда не время получения.**

| Источник | `observed_at` |
| --- | --- |
| Харнесс сообщает, когда замерил (Muse `observedAtMs`; метки времени `usage_report` Claude) | это время |
| Харнесс отдаёт живые данные вендора по контракту (Codex `account/rateLimits/read`) | время чтения |
| Харнесс может отдать кэшированные данные, не говоря когда (Claude `/usage` откатывается к полосам, загруженным за последние 60 минут, когда его запрос использования не удаётся, L1 §1.2) | парсер должен распознать откат. Когда он не может установить время замера, окно не несёт `observed_at` и становится `invalid`, то есть неизвестным. |

`retrieved_at` фиксирует, когда запись доставлена. Свежесть его никогда не читает.

**Частичное обновление никогда не освежает окно, которое оно не наблюдало:**

- Успешное pull-чтение заменяет весь список окон. Каждое окно, которое оно вернуло, несёт собственное время источника, а окно, которое оно больше не возвращает, отбрасывается.
- Push обновляет только окна, которые несёт, каждое со своим временем наблюдения. Нетронутые окна сохраняют своё.
- Неудачное чтение или push не меняет ни окон, ни `observed_at`. Оно добавляется в `failures` со своим временем, так что кэшированная запись хранит и сбой, и исходные возрасты.

**Чего роутер никогда не получает.**

- Никаких путей, имён хостов, адресов учётных записей и токенов.
- `home_display` производителя не попадает в проекцию для роутера и ни в одну запись решения.

### 3.1 Проекция на стороне роутера

Адаптер вызывающего замораживает записи в `CandidateSnapshot`. Эта проекция — единственный вход использования для стратегии (W1); то, как её строит task-board, — дизайн W4 и код W5.

```text
CandidateSnapshot (usage members)
    as_of               UTC Unix seconds; sub-second parts are truncated toward negative infinity
    scope_map           {version, entries[{runtime, scope, model_ids[]}]}; an empty map leaves every model-scoped window unmapped
    usage_facts[]       one per subscription key, ordered by key
        key             the record's identity (opaque)
        runtime
        state           exact | percent_only | last_observed | not_supported | unavailable | absent
        windows[]       ordered by id: {id, scope, minutes, used_bp, resets_at?, observed_at?, freshness}
        credits?        {balance, unit, unlimited}: shown by explain, never an ordering input
        record_digest
        failure_count
    inflight[]          {key, runs}, ordered by key
    candidates[]        each with its billing class and, for subscription billing, its usage key
```

**Единицы.** `used_bp` — это `used_percent` в базисных пунктах, округлённый half to even в момент заморозки. Метки времени — секунды Unix в UTC. Все целые — 64-битные.

**Допустимый диапазон.** Каждая метка времени (`as_of`, `observed_at`, `resets_at`) лежит между 946684800 (2000-01-01) и 7258118400 (2200-01-01), а `ttl_s` — между 1 и 86400. Снимок, чей `as_of` вне диапазона, отклоняется. Окно с меткой времени вне диапазона — `invalid`. В этих границах никакое вычитание или произведение не переполнится.

**Проверка.** Адаптер помечает `freshness` каждого окна:

| Свежесть | Когда |
| --- | --- |
| `invalid` | любое из: `minutes` вне 1–527040; `used_bp` вне 0–1000000; `observed_at` отсутствует; `observed_at > as_of`; `observed_at` или `resets_at` вне допустимого диапазона ниже |
| `expired` | `resets_at ≤ as_of`: окно сбросилось после наблюдения, так что его новое состояние неизвестно до обновления |
| `fresh` | `as_of − observed_at ≤ ttl_s` |
| `stale` | иначе |

## 4. Свежесть

- **Известно только окно `fresh`, валидное и неистекшее.** Окно `stale`, `expired` или `invalid` неизвестно (решение оператора: несвежее означает неизвестное). Его значения остаются в снимке для `explain`, но ни в один ключ упорядочивания не идут.
- **Сбой чтения — никогда не запас.** Запись в состоянии `not_supported` или `unavailable`, как и отсутствие записи, означает отсутствие известных окон.
- **Часы принадлежат вызывающему.** Адаптер читает часы один раз, замораживает `as_of` и помечает свежесть. У селектора часов нет (R6), а повтор использует замороженный `as_of`.

**Обновление.**

- Вызывающий планирует обновление после решения, когда запись несвежая, и никогда внутри шлюза запуска (EPIC D3, D8).
- TTL по умолчанию — 10 минут, с одним pull-чтением на `(runtime, home)` за TTL (EPIC D7).
- Push-обновления из хостимых сессий держат записи свежими без опроса.

## 5. Стратегия `headroom-aware`

`headroom-aware` оборачивает базовую стратегию (`config-order`, `quality-first` или `cost-with-quality-floor`, R6). Она никогда не меняет, какое качество выбрано. Она меняет только то, какая подписка его обслуживает, или какая из нескольких объявленных оператором эквивалентных пар.

### 5.1 Взаимозаменяемые группы

**Базовый контракт.** Базовая стратегия возвращает либо полный порядок всех пригодных кандидатов, позиции от 0 до n−1, либо отказ от выбора. Когда база отказывается, `headroom-aware` отказывается с причиной базы.

**Перестановка.**

- Запас переставляет кандидатов только внутри взаимозаменяемой группы.
- Слоты группы — это базовые позиции её членов; они неизменяемы.
- Каждая группа переставляется независимо в своих слотах. Кандидаты вне всех групп сохраняют позиции.

**Группы не пересекаются,** поэтому результат единственен:

| `equivalence` | Группа | Непересекаемость |
| --- | --- | --- |
| `same-pair-any-home` (по умолчанию) | кандидаты с одной средой выполнения, моделью и уровнем, различающиеся только управляемым домашним каталогом | по построению |
| `declared-groups` | оператор перечисляет группы пар, которые считает эквивалентными; ничто другое в группу не входит | проверяется при загрузке политики: пересечение после раскрытия отклоняет политику (`headroom_groups_overlap`), до любого решения |
| `fitness-band` (с оценщиком) | кандидаты, которых оценщик относит к одной полосе; вывод оценщика — разбиение, со ссылкой на его версию | по контракту оценщика |

**Переставляются только подписки.** Внутри группы двигаются только кандидаты с тарификацией `subscription`. Члены `metered` и `local` сохраняют слоты, потому что их стоимость — это слагаемое стоимости базовой стратегии (R6).

### 5.2 Величины на кандидата

Вся арифметика — 64-битные целые, в базисных пунктах (bp: 10000 = 100 %), так что повтор точен на каждой платформе.

**Применимые окна** — это окна факта с областью действия `all` плюс окна, ограниченные моделью, которые карта областей действия отображает на модель кандидата. Затем применяется фильтр `windows` из политики. Неотображённое окно, ограниченное моделью, игнорируется и добавляет `quota_scope_unmapped`.

Для каждого **известного** применимого окна `w` (§4):

| Величина | Определение |
| --- | --- |
| остаток | `r_w = max(0, 10000 − used_bp_w)` |
| осталось времени | при `d = min(resets_at_w − as_of, minutes_w · 60)`: `τ_w = floor(d · 10000 / (minutes_w · 60))`. Отсутствует, когда отсутствует `resets_at`. `d` положительно, потому что известное окно не истекло. |
| зазор | `s_w = r_w − τ_w`, в −10000…10000; только когда `τ_w` есть |

Наибольшее промежуточное значение — `527040 · 60 · 10000 ≈ 3.2 · 10^11`, с запасом внутри 64 бит.

Для кандидата:

| Величина | Когда определена | Значение |
| --- | --- | --- |
| over | всегда | 1, если у какого-то известного применимого окна `used_bp ≥ 10000`, иначе 0 |
| запас `H` | есть хотя бы одно применимое окно, и все они известны | `min_w r_w`: определяет самое тесное окно |
| зазор `S` | `H` определён и у каждого применимого окна есть `τ_w` | `min_w s_w`: недельное окно, которое быстро горит, перевешивает просторное сессионное окно |
| полоса `B` | всегда | `floor(S / band_width_bp)`, с округлением к минус бесконечности (не усекающим делением Go), когда `S` определена; иначе 0 |

**Неполные факты нейтральны.** Факт неполон, когда:

- нет применимых окон (`quota_no_applicable_window`);
- какое-то применимое окно несвежее, истекшее или невалидное (`quota_stale`, `quota_expired`, `quota_invalid`);
- известны лишь некоторые окна (`quota_partial`);
- запись отсутствует или нечитаема (`quota_unknown`).

Неполный факт получает `B = 0` («как будто в темпе»), без `H` и без резерва. Его единственный возможный эффект — `over` от известного окна. Частичное чтение поэтому никогда не даёт положительного предпочтения, а несвежее значение никогда не выставит кандидата полным или пустым.

### 5.3 Порядок внутри группы

Сортируйте по возрастанию этого ключа, затем расставьте членов группы по слотам группы в этом порядке:

1. **over.** Кандидат сверх квоты идёт последним, но не удаляется: `Limited` решает реактивный слой, потому что это устанавливает только запуск (L1 §3.1).
2. **reserve:** 1, если роль не защищена, `H` определён и `H < reserve_bp`; иначе 0. Защищённые роли (по умолчанию: orchestrator и reviewer) игнорируют резерв.
3. **−B:** сначала более высокая полоса. Мощность, которая сгорит при сбросе, используется раньше мощности, которую берегут.
4. **in-flight запуски:** сначала меньше. Счётчик — это стоящие в очереди и выполняющиеся запуски на этом `(runtime, home)` в `as_of`, его даёт вызывающий; роутер счётчиков не ведёт (R8). Ключ, которого вызывающий не дал, считается за 0 и добавляет `inflight_unknown`.
5. **позиция в базовом порядке.**
6. **идентификатор кандидата**, лексически.

Каждый шаг, решивший сравнение, добавляет код причины:

- `quota_over`, `quota_reserve`;
- `quota_expiring` при `B ≥ expiring_band`, `quota_on_pace`, `quota_conserve` при `B ≤ conserve_band`;
- коды неполноты из §5.2;
- `inflight_spread`.

Кредиты показываются в `explain` и в этой версии не входят в упорядочивание.

**Если все кандидаты в зоне резерва,** политика выбирает:

- `rank` (по умолчанию): порядок остаётся, записывается `reserve_breached`;
- `abstain`: стратегия отказывается, и `select` ничего не запускает (R7).

### 5.4 Параметры политики

Они входят в дайджест политики (R8):

```text
headroom
    enabled               default false; W5 turns it on in shadow mode first
    equivalence           same-pair-any-home | declared-groups | fitness-band
    groups[]              for declared-groups: lists of {runtime?, model, effort}
    protected_roles[]     default [orchestrator, reviewer]
    reserve_bp            default 2000
    band_width_bp         default 1000
    expiring_band         default +3
    conserve_band         default -2
    windows               all (default) | a list of window ids
    on_all_reserved       rank (default) | abstain
```

Политика проверяется при загрузке, никогда не на решение. Нарушение отклоняет политику:

- `band_width_bp ≥ 1`;
- `0 ≤ reserve_bp ≤ 10000`;
- `expiring_band > conserve_band`;
- непересекающиеся объявленные группы.

## 6. Чего это никогда не делает

- Оно никогда не запускает проб, не стартует процессов, не читает часы, не ведёт счётчики и не резервирует мощность.
- Оно никогда не убирает кандидата по запасу: сверх квоты и резерв лишь двигают кандидата внутри его группы, а отказ — явный выбор политики.
- Оно никогда не переключает учётки и маршруты. Другой управляемый домашний каталог — это другой целый кандидат (другая привязка среды выполнения), и выбрать его — значит выбрать вариант, а не править его (R7, R11).
- Оно никогда не меняет допуск. Допущенный набор один и тот же, что бы ни говорило использование. Это гарантия побайтового тождества из дизайна квот провайдеров, которая держится на стороне task-board.

## 7. Как знать остаток мощности в каждый момент

Взгляд оператора — не взгляд роутера. Это:

- `task-board q 'provider_quota()'`: кэшированные записи с их возрастом;
- `provider_quota(refresh=true)`: живое чтение, по одному на `(runtime, home)` за TTL;
- блок `quota` предварительной проверки (Lane 2, W5).

Хостимые сессии держат записи свежими через push, когда шов W4 построен:

- потоки диалога Codex app-server — через `account/rateLimits/updated`;
- Muse — через `usage/changed`;
- дочерние запуски Claude — через `rate_limit_event`, когда спавнер читает stream-json.

Собственный взгляд роутера — `cmr headroom explain --snapshot FILE`. Он печатает окна каждого кандидата с их свежестью, `H`, `S`, полосой, классом и кодами причин.

## 8. Приёмка (поток W1, стратегия)

Тестовые векторы, каждый повторяется из замороженных входов без часов:

1. **Сгорающее первым.** У двух домашних каталогов одной пары равные просторные недельные окна. Тот, чьё сессионное окно использовано на 20 % и сбрасывается через 30 минут, ранжируется раньше того, у кого окно тоже использовано на 20 %, но до сброса остаётся 4,5 часа.
2. **Недельное окно определяет результат.** Сессионное окно с большим зазором не выигрывает, когда у недельного окна той же записи отрицательный зазор ниже, чем у другого домашнего каталога.
3. **Несвежее, истекшее и невалидное нейтральны.** Такой факт ранжируется с полосой 0, без эффекта резерва и без `over` от этих окон, и показывает свои значения в `explain`. То же верно для окна, наблюдённого после `as_of`, и для окна, чьё время замера парсер не смог установить.
4. **Частичные факты ничего не получают.** Факт с одним свежим просторным окном и одним несвежим окном получает полосу 0 и никакого `H`.
5. **Редкие push.** Push, освежающий сессионное окно, оставляет нетронутое недельное окно несвежим, и факт остаётся неполным.
6. **Сверх квоты идёт последним и остаётся.** Кандидат сверх квоты — последний в своей группе и всё ещё на месте.
7. **Резерв по роли.** Кандидат-разработчик ниже резерва идёт после членов своей группы вне резерва. Кандидат-ревьюер игнорирует резерв.
8. **Распределение.** При равных полосах выигрывает домашний каталог с меньшим числом in-flight запусков.
9. **Двигается только группа.** Кандидаты metered и local, а также кандидаты вне всех групп, сохраняют слоты. Пересекающиеся объявленные группы отклоняют политику.
10. **Области действия.** Окно, ограниченное моделью, без отображения игнорируется со своим кодом причины. Факт без применимых окон неполон.
11. **Все в резерве.** `rank` и `abstain` ведут себя как объявлено. Отказ базы проходит сквозь.
12. **Целочисленно и детерминировано.** Зазор −1 bp — это полоса −1. Крайние границы `minutes`, `used_bp` и меток времени считаются без переполнения, а `as_of` вне диапазона отклоняет снимок. Дробные проценты округляются half to even. Те же входы дают тот же порядок на каждой платформе, а golden-файлы закоммичены.
